# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Changed
- Adopted `flutter_hooks` + `hooks_riverpod` for local widget state (IMPR-0007). New widgets that need controllers, focus nodes, timers, animations, or simple flags should use `HookWidget` / `HookConsumerWidget` instead of `StatefulWidget` / `ConsumerStatefulWidget` — `useTextEditingController()` replaces `final _c = TextEditingController()` + `dispose`, `useState(value)` replaces `setState`-only fields, `useEffect(() { ...; return cleanup; }, deps)` replaces `initState` + `dispose` pairs, `useMemoized(() => GlobalKey<FormState>(), const [])` replaces form keys. Existing `StatefulWidget`s aren't being bulk-migrated; they get converted opportunistically when the file is touched and the win is clear. `forgot_password_page.dart` and `log_selection_page.dart` migrated as canonical examples; CLAUDE.md and `.github/copilot-instructions.md` document the conversion table
- Refactored `recipe_edit_page.dart` to shrink its oversized methods (IMPR-0006). `_save()` went from ~110 lines of inline upload + Recipe assembly + persist into a 16-line orchestration plus six small private helpers (`_confirmUnsavedTag`, `_uploadPendingImages`, `_deleteRemovedImages`, `_newRecipeFromForm`, `_existingRecipeFromForm`, `_persistRecipe`) — each step is now scannable and individually testable. Three of the largest `build()` sections were extracted into self-contained `StatelessWidget`s — `_RecipeImagesSection` (was ~130 inline lines), `_RecipeIngredientsSection`, and `_RecipeInstructionsSection` — each taking the list it renders plus the relevant callbacks. No behaviour change
- Added 71 behavioural tests for high-bug-density modules to lock in the fixes from BUG-0028 through BUG-0033 (IMPR-0002): `test/gemini_helpers_test.dart` covers `isGeminiRateLimitError`, `parseGeminiRetryAfter`, and `stripCodeFences`; `test/calendar_sync_compare_test.dart` covers `eventInSyncWithGoogle` and `sameMoment` including the Firestore-round-trip DateTime case that caused BUG-0032's repeated patches; `test/markdown_toolbar_logic_test.dart` covers the detect-formats and toggle logic — caught a real `lastIndexOf(-1)` crash when the caret sits at offset 0 that was lurking in the original code; `test/autosave_snapshot_test.dart` covers the BUG-0033 snapshot equality. Required extracting four new utility files (`stripCodeFences` and the rate-limit helpers in `gemini_service.dart`, `lib/features/calendar/utils/sync_compare.dart`, `lib/features/knowledge/utils/markdown_toolbar_logic.dart`, `lib/features/{knowledge,recipes}/utils/autosave_snapshot.dart`) and replacing the in-state copies with delegations
- Split `settings_page.dart` (1202 lines, twelve unrelated tile widgets and three picker dialogs) into nine per-section widget files under `lib/features/settings/widgets/` — `ProfileSection`, `AppearanceSection`, `PreferencesSection`, `CalendarSection`, `DataSection`, `StorageSection`, `AiSection`, `WidgetsSection`, `AccountSection`. The shared `SettingsSectionHeader` and `CurrencyPickerDialog` (with its `currencyOptions` map and `currencySymbol()` helper) also moved out. `settings_page.dart` is now a 46-line thin composition page that just stacks the sections. No UI or behaviour change (IMPR-0004)

### Changed
- List subtitles and detail metadata now show the last-updated time instead of the created time so users see when an item was actually last touched, not just when it first appeared (WISH-0073). Specifically: conversation list tiles, feedback list tiles, and the catalog detail metadata line now use `updatedAt`. The catalog detail line shows `Updated X · created Y` when the two timestamps materially differ (≥ 1 minute), or just `Created X` when nothing has been edited yet. Conversation sort "newest/oldest" was also flipped to use `updatedAt` so recently-active topics float to the top — matches what the subtitle date now displays. Out of scope: "Member since" on profile / public-profile pages (semantically meaningful join date, not a generic created), admin invite "Created" (invites don't get updated), feedback clipboard export "Reported:" (date the bug was filed is the meaningful timestamp there), and CSV exports (machine-consumable archives keep `createdAt` as-is)
- Conversation list page now defaults to the Open status filter instead of "all" so users land on actionable topics rather than the noise of every resolved conversation. Resolved and all-status views are still one tap away via the existing filter chip (WISH-0071)

### Added
- Optional **fill percentage** on inventory items (WISH-0078) so half-empty bottles, almost-gone sauces, and partially-used bags can be flagged without changing the integer `quantity`. New `InventoryItem.fillPercent` field (nullable int, 0–100; null = "not tracked" and the UI hides the indicator). A "Track fill percentage" switch on the inventory edit form reveals a 0–100 slider (5%-step divisions) when turned on; default value is 100 when toggling on. The inventory list-tile subtitle now includes `X% full` when set (alongside category / location / quantity / expiry). Old items load cleanly because `fromMap` tolerates missing data. Six unit tests cover default-null behaviour, toMap/fromMap roundtrip, legacy-data tolerance, copyWith updates, `clearFillPercent`, and independence from `quantity`
- Drag-and-drop file upload on web + desktop (WISH-0077). New shared `FileDropTarget` widget (`lib/presentation/widgets/file_drop_target.dart`) wraps any region and catches files dragged in from the OS / browser instead of letting the browser open them in a new tab. While the drag is hovering, a translucent primary-tinted overlay with "Drop file" / "Drop image" label appears. Wired into three surfaces this round: the **Files page** (drop any image type into the current directory — uploads straight to Storage and adds an entry), the **Knowledge editor** (drop images to attach them to the page; uploads via `uploadFileBytes` so quota is tracked), and **Feedback editor** (drop a screenshot — goes through the standard preview / crop / quality dialog, then uploads). Other image upload edit pages (recipe, inventory, calendar event, conversation, task, catalog) can opt in with the same one-line wrap. Mobile is a no-op since users don't drag onto mobile apps. Currently supports image formats (PNG / JPEG / GIF / WebP / TIFF / BMP); non-image drops are intercepted (so the browser doesn't open them) and logged as a TODO until the virtual-file reader path lands. New `super_drag_and_drop: ^0.9.0` dependency (same vendor as the existing `super_clipboard`)
- New top-level **Contacts** feature for managing the people and groups conversations are about (WISH-0076). Lives at `/contacts` (linked from More) and is intentionally distinct from the existing "People" feature, which is about other app users' public profiles. Each contact stores name, optional email / phone / date of birth, free-form notes, and an `isGroup` flag for families / teams. Full CRUD via a list page (search + add) and an edit page (delete via AppBar). Persisted under `users/{userId}/contacts/` in Firestore via the standard service-abstraction pattern (`ContactService` + `FirestoreContactService` + `MockContactService`). Conversations now link to a contact via a new optional `contactId` field on `ConversationTopic`: the conversation edit form's "Person / Group" input is now a picker (existing contacts list + "New contact…" + "Use a name without linking" fallback) instead of a free-text autocomplete, and the conversation list tile displays the linked contact's name when one is set (falling back to the legacy `personOrGroup` string for pre-WISH-0076 conversations so nothing breaks on upgrade). Added five tests covering Contact model roundtrip, minimal-contact defaults, isGroup persistence, and copyWith behaviour
- Tap-to-enlarge image viewer across the app (WISH-0075) — a new shared `FullscreenImageViewer` widget opens images in an interactive viewer with the correct aspect ratio, pinch-to-zoom + pan via `InteractiveViewer`, and tap-anywhere / close-button dismissal. Wired into the obvious "view" surfaces: recipe detail (hero image, image carousel, per-instruction step images), catalog detail (image carousel), public profile photo (only when the user has one), and knowledge view page image attachments (other file types still launch externally). Also wired into the image preview grids on every edit page that didn't already have a meaningful thumbnail tap — inventory, catalog, calendar event, conversation, feedback, and task edit pages. Recipe edit page's thumbnails are intentionally left alone because their tap already does something (sets the primary image); same for the profile photo edit (tap opens the change-photo dialog). List-tile thumbnails are also untouched so list navigation still works as before. Two entry points: `showFullscreenNetworkImage(context, url)` for download URLs and `showFullscreenMemoryImage(context, bytes)` for pending uploads
- Optional Android fullscreen / immersive mode (WISH-0074) — a new "Fullscreen mode" switch in Settings → Appearance hides the system status bar and navigation bar; swiping in from a top or bottom edge reveals them temporarily and they auto-hide again. Wired via `SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)` when enabled; flipping it off reverts to the default `edgeToEdge` UI. The toggle is only shown on Android — iOS / web / desktop don't have an equivalent system bar concept, so exposing the option there would be misleading. Persisted as `fullscreenMode` on `UserSettings` (default false) so the setting follows the user across devices. Added unit tests for the new setting (default value, toMap/fromMap round-trip, copyWith)
- Paste image from clipboard + desktop crop support across every image upload surface (WISH-0072). All eight image source pickers (recipes — including the step-image picker, inventory, tasks, catalog, feedback, calendar events, conversations, profile) now offer a "Paste from clipboard" entry alongside Gallery/Camera. Clipboard reads use `super_clipboard` and accept both PNG and JPEG, so copying an image directly off a web page (or out of any other app) and pasting it into the upload dialog now works without saving to disk first. Two source pickers that previously went straight to the gallery (catalog, profile) gained a bottom sheet to expose the new option. Image cropping (introduced in WISH-0070) was native-only and broke on Windows/Linux/macOS; the Crop button now routes to a Flutter-rendered `crop_your_image` page on those platforms while keeping the polished UCrop/PhotoEditor UI on Android/iOS. Both the source picker and the cropper are wired through one shared helper (`resolveImageSource` + `PasteFromClipboardTile`) so future upload sites get paste support automatically by including the tile and dispatching through the helper. New deps: `super_clipboard: ^0.9.0`, `crop_your_image: ^2.0.0`
- Image cropping + opt-in source removal in the shared image upload dialog (WISH-0070). The preview dialog now exposes a "Crop" button (via `image_cropper`'s native UCrop/PhotoEditor UI on Android/iOS; hidden on web/desktop) that runs before — and composes with — the existing Original / Good / Compressed quality selector. When the dialog is shown for an image picked from gallery or camera (i.e. `sourcePath` is supplied), it also offers a "Remove from device after upload" checkbox; checking it triggers `ImageUploadService.tryRemoveSourceAsset` after the user confirms Upload, which uses `photo_manager` to find the matching asset in the user's photo library and asks the OS to delete it (the OS shows a confirmation dialog the user can still refuse). All ten existing image upload surfaces — recipes (form + instruction picker + image dialog), inventory, tasks, catalog, feedback, calendar events, conversations, and profile — now pass `sourcePath` and call `result.maybeRemoveSourceFromDevice()` after the dialog returns. New `image_cropper: ^9.1.0` + `photo_manager: ^3.6.4` dependencies; Android manifest registers `UCropActivity` + `READ_MEDIA_IMAGES`/`READ_EXTERNAL_STORAGE`; iOS Info.plist gains `NSPhotoLibraryUsageDescription`, `NSPhotoLibraryAddUsageDescription`, and `NSCameraUsageDescription`. Crop and source-removal are both best-effort: cropping falls back to the original bytes if the cropper fails, and removal silently no-ops on web or when the asset isn't found / permission is denied
- New top-level Files feature (WISH-0069) — a `/files` page reachable from More that lets the user upload, browse, and organize arbitrary files independently of the Knowledge Bank. Supports nested directories (e.g. a `work/` folder with files inside), with a breadcrumb at the top, an "up one level" button, and per-row rename/delete actions. AppBar sort menu toggles between Name and Last updated (directories always cluster above files within the chosen sort). New folders are created via an AppBar icon; uploads go through the existing `pickAnyFile()` + `uploadFileBytes()` path so the user's storage quota is enforced and tracked the same way as knowledge attachments — files land under `users/{userId}/files/` so the `onFileUploaded` / `onFileDeleted` storage triggers keep `storageUsedBytes` in sync without feature-specific bookkeeping. Deleting a folder cascades recursively to remove every nested file and folder (Firestore docs + Storage blobs). No WIP status — the user explicitly didn't want one for files. Added `lib/features/files/` (model, abstract + Firestore + Mock service, providers, page) and `test/file_entry_test.dart` covering model roundtrip and `copyWith` semantics
- Knowledge pages can now have arbitrary file attachments (WISH-0068) — pick any file type via the new "Attachments" section in the knowledge editor; the file uploads to Firebase Storage under `users/{userId}/knowledge/` so the existing `onFileUploaded` Cloud Function trigger increments the user's `storageUsedBytes` automatically. Hitting the storage limit shows a snackbar with the remaining quota. Each attachment is rendered with name, content type, and size on both the edit and view pages; tapping opens it in the browser. Removing an attachment during an edit session marks it for deletion on save; deleting the whole page cascades to remove every linked file from Storage. `ImageUploadService` gained `pickAnyFile()` + `uploadFileBytes()` (with a small extension-to-MIME map) on top of the existing image-specific path, and `KnowledgePage` gained an `attachments: List<KnowledgeAttachment>` field. New `file_picker: ^8.1.4` dependency
- Third feedback category: "Improvement" (alongside Bug and Wish) — for refactors, cleanups, perf work, dead-code removal, observability, and other non-functional quality work that doesn't fit "bug" or "wish". The list page filter, type chip (teal `Icons.tune`), edit-form segmented selector, and clipboard export all recognize the new type. Auto-generated reference IDs use the `IMPR-NNNN` prefix
- New `createFeedback` Cloud Function (HTTP, Bearer auth via the existing `FEEDBACK_API_KEY` secret) so an AI assistant can file a bug / wish / improvement directly into the feedback database without going through the app UI. The function scans both the public collection and every user's private collection to pick the next non-colliding reference ID for the requested type. Accompanying `scripts/create-feedback.sh` wrapper mirrors the existing `update-feedback-summary.sh` script. `CLAUDE.md` and `.github/copilot-instructions.md` now describe when (and when not) to file items vs. fixing them inline
- Gemini can now authenticate via "Sign in with Google" instead of an AI Studio API key — pick the mode in Settings → AI → Authentication mode. With OAuth, quota counts against your own Google account so there's no key to copy/paste and no rate limits tied to a shared project. The existing API-key flow is unchanged. Internally GeminiService was rewritten on direct HTTP (dropping the `google_generative_ai` SDK) so both auth modes flow through one code path — same request format, just different auth (URL `?key=` for API key, `Authorization: Bearer` header for OAuth). The OAuth scope is `cloud-platform`; uses a separate `GoogleSignIn` instance from the calendar integration so the two connections are independent. All Gemini surfaces (chat, recipe AI, knowledge AI assist, inventory image scan) work with both modes (WISH-0067)
- Tasks can now have subtasks — pick a parent task in the edit form (only root tasks are eligible; one nesting level keeps the model simple and prevents cycles). Root tiles in the task list show a `2/5 subtasks` badge with a tertiary tint when complete, and subtasks render indented underneath their parent. A parent can only be marked done when all its subtasks are complete (snackbar with the remaining count if you try); uncompleting a parent is always allowed. Deleting a parent unlinks its subtasks rather than cascading — they become root tasks. Existing tasks with no parent are unaffected (WISH-0065)
- Polling-based Google → local Calendar sync — edits made directly in Google Calendar are now pulled back into linked local Firestore events on three triggers: when the user first connects Google Calendar in a session, when the app returns to the foreground, and every 15 minutes while the app is open. Google wins for title/description/date/endDate/isAllDay; local-only fields (imageUrls, sourceId, color) are preserved. The Calendar AppBar's integrations menu also gets a "Sync from Google now" item (only when connected) for an on-demand pull, and the sync now also deletes linked local events that were removed in Google — but only when the local event's date sits inside the ±2-month fetch window so we don't false-positive events outside the fetched range. The events.watch webhook flow is still pending and will require an OAuth offline-access architecture change plus a deployable Cloud Function (WISH-0066)
- Toggleable side-by-side markdown preview in the knowledge editor — on screens at least 900px wide a preview icon appears in the AppBar; toggling it splits the content area into editor (left) and live-rendered preview (right) using the same `MarkdownBody` configuration as the view page (selectable, tappable links). Below the breakpoint the toggle is hidden and the editor stays full-width (WISH-0063)
- Knowledge editor markdown toolbar now highlights the active formatting and toggles it off when re-clicked — H1/H2/H3, bold, italic, inline code, bullet list, numbered list, and blockquote buttons all detect the format at the current cursor or selection (line-prefix headings/lists/quotes work with a collapsed cursor; inline wrappers require a non-empty selection that's either inside the markers or that fully encloses them). Toggling a heading also strips the optional CommonMark trailing `## ` close so cleanup is symmetric with creation. Link and horizontal-rule buttons stay insert-only since they have no symmetric "active" state (WISH-0064)
- Recipe detail page redesigned with a 3-tab layout — General (images, tags, description, components, videos, notes, source), Ingredients (with live servings scaling), and Instructions (numbered with step images). Servings adjuster, prep time, and cook time stay pinned at the top across all tabs. The bottom navigation bar is now hidden on `/recipes/:id`, `/recipes/:id/edit`, and `/recipes/new` to give the recipe content full vertical space (WISH-0062)
- AI editing for existing recipes — the recipe edit page now shows an "Edit with AI" wand icon (next to the existing "Create with AI" sparkle, which only appears for new recipes); enter an instruction like "make it vegetarian" or "double the servings" and Gemini receives the current form data plus the instruction and returns an updated recipe in the same JSON schema. Mirrors the existing AI Assist on knowledge pages, reuses the rate-limit handling and developer logging from BUG-0029/BUG-0030 (WISH-0061)
- WIP Items home-screen widget (Android) — aggregates work-in-progress items from recipes, knowledge, shopping, and feedback; emoji-prefixed first 5 items + total count; tracks the user's accent color; tapping the widget opens a new `/wip` overview page that lists every WIP item grouped by source with tap-through to each item's detail page; pinning shortcut available in Settings → Widgets next to the existing Daily Task Preview shortcut (WISH-0060)

### Changed
- Settings → AI now states honestly that the Gemini OAuth path runs against the app developer's Cloud project, not the signed-in user's. The auth-mode subtitle, the OAuth selection dialog, and a new inline info banner above the OAuth tile all say this clearly so users aren't misled into thinking OAuth means "my own quota and models" — which it doesn't on `generativelanguage.googleapis.com` without an `x-goog-user-project` header / GCP project setup that we deliberately chose not to add (BUG-0036 follow-up). API key mode remains the path for users who want their own quota / project's model list

### Fixed
- Parent-task picker on the task edit form no longer offers completed tasks (BUG-0044). The candidate list previously included every root task ever created, including the long tail of finished ones — chaotic to scroll through and rarely what the user actually wants. Added `!t.isCompleted` to the existing filter (alongside the "not yourself" and "not already a subtask" rules); the dropdown only shows actionable parents now
- Decimal input now accepts both `,` and `.` as the decimal separator (BUG-0043). Typing `1,5` for a price, asset value, transaction amount, or recipe ingredient quantity used to silently parse as `0` because `double.tryParse` is dot-only; the seven input sites that handled user-typed decimals (catalog price, inventory price, asset value + validator, transaction amount + validator, recipe ingredient quantity) now go through a single `parseDecimal()` helper in `lib/utils/decimal_input.dart` that normalises `,` → `.` before parsing and trims whitespace. Validators on the asset and transaction forms use the same helper so the "Invalid number" check matches what actually gets parsed on save. Ten unit tests cover both separators, negative numbers, whitespace tolerance, null/empty input, and rejection of garbage like `1.2.3`. The thousands-separator case (`1,000.0`) is intentionally not supported — nobody types that into a single price field
- Date format can now be overridden in Settings — dates used to show in `MM/DD/YYYY` whenever the system locale resolved to `en_US`, even for users who think in `DD/MM/YYYY`. Added a "Date Format" tile to Settings → Preferences with curated choices (Device default / Day-month-year European (`en_GB`) / Month-day-year US (`en_US`) / Dutch / German / French) — each row shows a live example so it's obvious which one produces `9 Jun 2026` vs `Jun 9, 2026`. Persisted as `UserSettings.dateFormatLocale` (`null` = follow device). Applied globally via `Intl.defaultLocale` so every existing `DateFormat.yMMMd()` / `.yMMMM()` / etc. call across the 21 sites that use them picks up the new format on next rebuild — no per-call refactor needed. `main()` now calls `initializeDateFormatting()` so any chosen locale has its symbol data available. Four unit tests cover the default, roundtrip, copyWith, and clear semantics (BUG-0042)
- File uploads on web (Knowledge attachments + Files page) no longer silently do nothing — tapping the upload control now actually opens the browser's file picker. `file_picker` 8.x had a web regression where `fp.FilePicker.platform.pickFiles(...)` could fail to register on the web platform without surfacing an error. Upgraded the dependency to `file_picker ^11.0.2` (which dropped the `.platform.` intermediate in its public API and properly registers its web plugin) and switched the call to `fp.FilePicker.pickFiles(...)`. Native platforms continue to work unchanged (BUG-0039)
- Windows launcher icon no longer shows the default Flutter chevron — `flutter_launcher_icons` was configured for Android / iOS / web but not for Windows, so `windows/runner/resources/app_icon.ico` was still the project-bootstrap default. Added a `windows: { generate: true, image_path: assets/app_icon.png, icon_size: 256 }` block to the pubspec config and ran the generator; the .ico is now derived from the same `assets/app_icon.png` used on every other platform (BUG-0038)
- Gemini chat no longer crashes with an unhandled Dart exception when the API returns HTTP 429 / `RESOURCE_EXHAUSTED` (e.g. "prepayment credits depleted") (BUG-0037). `GeminiChatNotifier.sendMessage` previously caught `GeminiScopeException` but let `GeminiRateLimitException` fall through. It now extracts the human-readable `error.message` from the API body, prefixes it with a warning, and appends it as a bot chat message together with a hint pointing the user at Settings → AI → Gemini Model so they can switch to a model that still has free-tier quota. The model picker in settings already uses the metadata `/models` endpoint (no generation quota consumed) so it remains usable even when the project's prepayment credits are depleted
- Gemini OAuth requests no longer fail with HTTP 403 `ACCESS_TOKEN_SCOPE_INSUFFICIENT` (BUG-0036). The Gemini sign-in flow used to request the `cloud-platform` scope — that's the right scope for Vertex AI at `aiplatform.googleapis.com`, but `generativelanguage.googleapis.com` rejects it on `models.generateContent`. Switched to `generative-language.retriever`, which is the scope Google's own Gemini OAuth quickstart uses and the one the API actually accepts for inference (despite the misleading name). Bumped the persisted scope version so users with a stale `cloud-platform`-only token are auto-disconnected on next launch and prompted to re-authorize. Also added typed `GeminiScopeException` handling: when the API still comes back with scope-insufficient (e.g. someone copies a stale token across devices), the service auto-disconnects the OAuth session and the chat surfaces a clear "Open Settings → AI, disconnect, then sign in again" message instead of a silent failure. Required Google Cloud setup is unchanged — the Generative Language API needs to be enabled on the user's project and the new scope is non-sensitive so it doesn't require app verification
- Inventory items can now be deleted from the edit page — a trash-can icon next to the AI-scan action in the AppBar opens a "Delete \"<name>\"?" confirmation and, on confirm, calls the existing `inventoryListProvider.deleteItem` (which already cascades Storage cleanup for attached images). The list-page swipe-to-dismiss already worked but was easy to miss; the edit-page button matches how recipes and calendar events offer delete (BUG-0035)
- Android `flutter build apk --release` (and `flutter run --release`) no longer fails on the `androidx.compose.remote:remote-creation-android` / AGP 9.1 / compileSdk 37 chain. The `home_widget` plugin uses a dynamic version range for `androidx.glance:glance-appwidget`, and once Google published `1.3.0-alpha01` to Maven, Gradle started resolving to that alpha — which transitively pulls in `compose.remote` and requires a toolchain Flutter stable doesn't support yet. Pinned glance to `1.1.1` via `configurations.all { resolutionStrategy.force(...) }` in `android/app/build.gradle.kts`. Windows desktop and web builds were unaffected. Remove the pin once `home_widget` pins glance itself or Flutter ships a toolchain that supports AGP 9.1 (BUG-0034)
- Autosave on knowledge pages and recipes no longer fires repeatedly when a browser tab returns to focus — browser-throttled `Timer.periodic` ticks can pile up while a tab is suspended and all fire at once when it regains focus. Both editors now skip ticks that arrive within 80% of the configured autosave interval, and additionally skip the save entirely (no Firestore write, no snackbar) when the current form state matches the snapshot from the previous save (BUG-0033)
- Google Calendar OAuth popup loop on the web build — `AppLifecycleState.resumed` fires every time the OAuth popup closes on web, so the WISH-0066 sync ticker was kicking off a fresh sync on every popup close, which itself opened a new popup, in an indefinite loop. The ticker's lifecycle-resume listener and 15-minute timer are now skipped entirely on web (web users still get the initial-on-connect sync and the manual "Sync from Google now" action). Added a re-entry guard inside `syncFromGoogle` for defensive correctness on every platform. Also tightened the post-sync compare so we don't re-patch the same event every poll: `_isInSyncWithGoogle` now compares DateTimes by `microsecondsSinceEpoch` so a Firestore-round-tripped naive DateTime equals Google's `.toLocal()`'d DateTime when they represent the same moment, and `syncFromGoogle` now ignores automatic triggers that arrive within 10s of the previous one (the manual button passes `force: true` to bypass the cooldown) (BUG-0032)
- Calendar events that exist in both the app and Google Calendar are no longer shown twice — local events now persist a `googleEventId` after the initial push to Google, the merge provider drops Google fetches whose raw ID matches a linked local event, and updates/deletes on linked events are pushed to Google so the two sides stay in sync. Existing pre-fix duplicates need a one-time manual cleanup since they were created before the link was being stored. Edits made directly in Google Calendar still need a separate fetch round to reflect locally; full Google→local pull-on-fetch is out of scope for this change (BUG-0031)
- Knowledge page Contents panel no longer shows trailing `#` markers — closing ATX heading hashes (e.g. `## My Heading ##`) are stripped from the table-of-contents text while inline `#`s without preceding whitespace (like `C#`) are preserved (BUG-0028)
- AI recipe generation failures now report the actual cause — the Gemini service logs every failure path (auth missing, empty response, JSON parse error, API exception) via `LogService` so they appear on the developer page; the JSON-fence stripping regex was also fixed (`^```json?` only made the `n` optional, not the whole `json` literal); the recipe page now catches unexpected exceptions and surfaces the message in the snackbar (BUG-0029)
- Gemini rate-limit (HTTP 429 / quota exceeded) errors are now surfaced explicitly — `GeminiService` throws a typed `GeminiRateLimitException` (with parsed retry-after duration), and the recipe AI flow shows a snackbar with the wait time and a "View limits" action that opens https://ai.dev/rate-limit (BUG-0030)
- Recipe and knowledge AI flows now respect the user's selected Gemini model — both pages used to call `geminiService.configure(apiKey)` without passing the model, so the service kept its hardcoded default; both now pass `model:` on first configure and call `setModel()` on warm path, mirroring how chat and inventory image-scan already work. Default model also bumped from `gemini-2.0-flash` to `gemini-2.5-flash`
